# QQ群聊总结 · v0.9.37

让 AstrBot 按需或定时总结 QQ 群聊。插件通过 NapCat / OneBot v11 记录指定群的新消息，保存在本地 SQLite；你可以私聊机器人查询，也可以设置每日或单次任务，把总结发送到 QQ 私聊或邮箱。

**自动任务默认关闭，需要自行添加。**任务运行前会尝试从 NapCat 补读所选时段的群历史，但 QQ 接口可能只返回部分离线消息。报告会标明实际读取范围和补读状态，不保证完整覆盖未在线期间的聊天。

适用环境：AstrBot 4.9.2+（4.x）、Python 3.10+、NapCat / OneBot v11。图形化任务和设置页面需要 AstrBot 4.24.1+。无需额外 Python 依赖；插件使用 AstrBot 已配置的聊天模型，不需要在插件中另填模型 API Key。

| 能做什么 | 使用前要知道 |
| --- | --- |
| 记录并按需查询指定 QQ 群的消息 | 只保存配置生效后收到的消息；离线历史补读依赖 NapCat 返回结果 |
| 每日或单次自动总结 | AstrBot 和 NapCat 需在任务执行及补读期间运行；仅打开网页不够 |
| 发送到 QQ 私聊或邮箱 | QQ 私聊需要机器人在线；邮箱需要 SMTP 授权码和可用的聊天模型 |
| 读取图片、引用和转发 | 图片识别依赖视觉模型；语音、视频和文件正文暂不解析 |

## 安装与首次测试

1. 从仓库的 Releases 下载 `astrbot_plugin_group_memory-v0.9.37.zip`，在 AstrBot 插件管理中上传安装包并重载插件。GitHub 页面自带的 **Code → Download ZIP** 是源码包，不是插件安装包。手动安装源码时，把含 `main.py` 和 `metadata.yaml` 的目录命名为 `astrbot_plugin_group_memory`，放到 `data/plugins/` 下，确认路径为 `data/plugins/astrbot_plugin_group_memory/main.py`。
2. 在插件详情页打开「QQ群聊总结」→「插件设置」，逐个添加**要记录的 QQ 群号**和**允许查询记录的 QQ 号**，然后点击「保存插件设置」。群号列表为空时不会采集任何群。若当前 AstrBot 没有该页面，请先确认版本是否达到 4.24.1。
3. 确认 AstrBot 已通过 NapCat 接入该 QQ 群，并在当前人格/Agent 中启用 `qq_history_groups`、`qq_history_read`、`qq_history_media`、`qq_history_media_batch`；若要用自然语言管理定时任务，还要启用 `qq_auto_summary_manage`。模型需要支持工具调用。
4. 让群里产生几条新消息，用授权 QQ **私聊**机器人发送 `/群记录自检`，检查记录和 QQ API。然后私聊机器人：“总结群 123456789 今天的聊天。”

群号 `123456789` 只是示例。**私聊发起的总结只回复私聊；在群里发起的请求会按 AstrBot 的群聊回复设置处理。**

`/群记录自检` 只在授权 QQ 私聊或 WebChat 回复，群里调用不会发消息。它显示各配置群在保留期内的记录数量和最新保存时间，并用 `get_login_info` 检查当前 QQ API；只检查视觉模型 ID 是否填写，不调用 AI。媒体失败按原因计数；近期耗时分开显示记录库、QQ 接口、识图模型和工具调用。统计仅在本次插件运行期间保存在内存，最多保留每类最近 50 次耗时，重启清零；并行或互相包含的耗时不能相加。自检成功不保证历史图片一定可读。

## 怎么提问

> 总结群 123456789 今天的已保存聊天，重点列出重要讨论和有用资源。

> 总结群 123456789 上次总结后新增的聊天。

> 总结群 123456789 最近 1 小时的聊天，也读取图片、引用和转发；未读到的内容请说明。

“上次总结后”首次使用会从当天 00:00 开始；只有全部文字分页读完，进度才更新。若无新增已保存消息，会简短告知，不再读取媒体或生成四栏报告；空结果不会推进检查点。若要重查一段内容，请指定日期或时间范围。群内查询只能查当前群；跨群查询请私聊机器人。

总结固定为四栏：**重要讨论、有用资源、你的待办与提醒、待确认的信息**。重要话题的加粗标题单独成行；资源要写清内容或用途及原始链接。第三栏只放有证据与你有关的事项，不能把群友自己的计划写成你的待办。报告顶部用实际已读消息的首末时间和条数；未解析媒体在末尾简要说明。模型仍可能遗漏或误解内容，重要决定请核对原消息。

## 自动总结（可选）

**AstrBot 4.24.1 及以上**：打开插件详情页的「QQ群聊总结」→「自动推送」，选择群聊、接收方式、推送方式、时间和消息读取范围。QQ 私聊任务需要选择收件 QQ 号；邮箱任务使用 AstrBot 默认聊天模型。

- **每天**：选择推送当天或前一天的消息。**仅一次**：选择保留期内的消息日期及当天的推送时间。新建任务的读取范围包含开始和结束时间所在的整分钟。跨午夜时，以结束所在日期为所选读取日期；例如选“前一天”、20:00—08:00，读取推送前两天 20:00 至前一天 08:00:59。
- 任务卡片可修改、取消任务，并查看最近结果、实际读取时段、条数和补读状态。旧任务升级前的执行不会补造统计；升级前未设读取时段的任务继续按增量读取，直到修改时段。旧任务原有的结束边界在修改前保持不变。
- QQ 私聊收件号须加入「允许查询记录的 QQ 号」，并先私聊机器人一次，确保该会话有可用模型。尚无已保存记录的群暂不会出现在任务页面的群列表中。

邮箱授权码默认遮挡；在「插件设置」中点击「查看」才会读取已保存的授权码，离开页面或 30 秒后重新遮挡。

**邮箱接收**：先在同一页面「插件设置」→「邮箱发送设置」中填写 SMTP 服务器、端口、加密方式、用户名和 SMTP 授权码；发件邮箱通常与用户名相同，可留空。切换「自动推送」标签，接收方式选「邮箱」，填写收件邮箱并保存任务，点击任务旁「测试邮箱」。发送使用 SSL/TLS 或 STARTTLS，一封邮件包含排版后的 HTML 报告和完整纯文本备选版本，不拆段、不创建报告附件。邮件突出重要讨论与有用资源，原始链接可点击；主题显示群聊名称（若设置）、群号与实际读取日期。授权码在 AstrBot 面板中遮罩，但 AstrBot 会将配置值写入自己的配置文件；请使用服务商提供的专用授权码，并保护 Docker 数据卷。若聊天模型仍可用，邮箱任务在 QQ 掉线时也可发送数据库中已有的文字记录；掉线期间不会产生新的群记录，且本次无法读取新的图片。状态「已提交邮件」表示 SMTP 服务器接受了邮件，不保证邮件已进入收件箱。

QQ 邮箱示例：SMTP 服务器 `smtp.qq.com`、端口 `465`、加密 `SSL/TLS`、用户名填写完整的 `你的QQ号@qq.com`、授权码填写 QQ 邮箱生成的 SMTP 授权码。「发件邮箱」留空，或与 SMTP 用户名完全相同。「收件邮箱」可另填目标地址。若测试显示「SMTP 拒绝发件地址」，先核对发件邮箱与登录的 SMTP 用户名；插件会显示服务器代码，但不会回显服务器原文或授权码。

AstrBot 版本较旧或习惯私聊操作时，可用**已授权的 QQ 号私聊**机器人发送以下命令。安装或升级后不会自动创建任务；群聊和 WebChat 不能设置 QQ 私聊推送。

```text
/自动群总结 添加 123456789 20:00
/自动群总结 列表
/自动群总结 取消 123456789
/自动群总结 删除 1
```

时间为北京时间，每个任务每天运行一次；**添加后不会立刻总结**，如果设置时当天的计划时间已经过去，从次日开始。你也可以在私聊中直接说“每天 20:00 自动总结群 123456789，只发给我”，但需在 Agent 中启用 `qq_auto_summary_manage`，并确认它实际创建了任务。任务只推送到创建任务的**当前 QQ 好友对话**，不会向群里发送总结。`取消 群号` 会删除你为该群设置的全部时间，`删除 编号` 只删除一项。

没有收到推送时，查看任务卡片中的状态：`待运行` 表示尚未执行；`无新增已保存记录，未推送` 仅适用于未设读取时段的旧增量任务；`QQ接入不可用，等待重试` 表示 QQ 接口暂时不可用，每分钟限频重试；`失败：生成总结（NetworkError）` 表示模型请求失败；`失败：发送QQ私聊（ActionFailed，retcode …）` 表示 NapCat 拒绝发送；`失败：发送邮件（SMTP…）` 表示邮件连接、认证或收件地址出错。任务旁的「发送测试私聊」或「发送测试邮件」只发送一条短测试消息，不生成总结。QQ 和邮箱都一次发送完整报告；发送失败不会推进已成功推送的位置。旧版本任务会保留原有 QQ 接收方式。

通过私聊命令建立且未设置读取时段的旧任务，首次从设置当天 00:00 的已保存记录开始，之后按上次**成功推送**的位置读取新增记录；没有新增记录时不推送。页面设置了读取时段的任务，按选择的日期读取完整时段；此前读过的同一时段仍可重新生成总结。时段内无已保存记录时发送简短通知，不调用总结模型。每日任务若因插件停机或调度延迟错过时间，会在计划时间后 14 小时内按原计划日期补发；超过补发期限则标明是哪天未推送，下次仍按计划执行。设置时间晚于当天计划时间的新任务不会补发设置之前的时段。单次任务只在所选推送日期运行一次，计划时间后超过 30 分钟会跳过。超过保存期的旧消息仍无法恢复。

自动任务不再按 1000 条或固定分段数截断已保存记录，会分批读取、提取并汇总所选时段内的全部可用消息；记录越多，运行时间和模型调用量越高。开启「自动推送识别图片」后，插件会尝试本次纳入总结记录中的每张图片，不再设置图片数量上限；成功的识图文字会缓存，旧图片优先向 NapCat 请求新地址。取不到图片或模型识别失败会计入失败，不会伪称已读。关闭该选项后，自动总结只用文字，按需查询不受影响。合并转发正文暂不在自动任务中展开。QQ 私聊任务使用所选 QQ 会话当前的聊天模型；邮箱任务使用 AstrBot 默认聊天模型，可能产生模型调用费用；图片多时等待更久。自动推送的 QQ 报告采用纯文本，邮件另用 HTML 排版；重点讨论保留必要背景、分歧和结果，资源保留具体内容、用途和原始链接。发送前会检查四栏及重点条目的格式，并保留本次资料中可追溯的链接、文件、明确步骤和有具体用途的工具；格式不合格时额外请求模型修正一次。此检查不能验证群友说法的外部真伪。

群消息到达时，插件只写入 SQLite，不调用模型；若 AstrBot 的其他功能会自动回复群消息，那部分模型消耗由相应功能产生。QQ 私聊推送需要 NapCat 中的机器人 QQ 保持在线；邮箱接收不依赖 QQ 发送接口，但仍需 AstrBot 能获取所选 QQ 会话的聊天模型。每天和单次任务执行前都会尝试通过在线的 NapCat 分页补读对应时段的群历史，并按消息 ID 去重；未设置读取时段的旧每日任务从上次成功推送后补读。计划只在推送前上线时，请提前启动 AstrBot 和 NapCat，并保持运行直到任务完成；网页可以关闭。单次任务卡片的「补读记录」可提前测试，不会立即生成总结。接口超时、分页停滞或只返回部分离线消息时，报告会标明补读状态，不能据此声称全天完整。

## 常用设置

| 设置 | 建议 |
| --- | --- |
| 记录这些 QQ 群 / 允许查询的 QQ 号 | 必填；各填一个或多个号码。收件 QQ 号须在允许查询列表中。 |
| 本插件保留记录（天） | 默认 30 天；插件只查询这段期限内已保存的消息，更早的本地记录会在后续清理时删除；不影响 QQ 原聊天记录。 |
| 允许读取媒体（总开关） | 默认开启；关闭后两种总结都不识图。 |
| 识图模型 | 从 AstrBot 已配置的视觉模型中选择；留空则不识图。 |
| 自动推送识别图片 | 默认开启；尝试本次记录中的全部图片。关闭后自动推送只用文字。 |
| 按需总结的图片范围 | 默认“全部媒体”；“重点媒体”更快，仅影响手动提问。 |
| 批量识图并行数 | 默认 4，范围 1～4；视觉模型或 QQ 接口限流时可调低。 |
| QQ 取图单次等待（秒） | 默认 25 秒，范围 5～60 秒。调低会更快报告超时，也可能错过慢响应。 |
| 邮件推送：SMTP | 仅邮箱接收任务需要；填服务商地址、端口、SSL/TLS 或 STARTTLS、用户名及授权码。 |

### WebChat 查询（可选）

在 AstrBot ChatUI 发送 `/群记录身份`，将返回的 `reader_id` 在插件页面逐个添加为网页查询者，并打开“允许从 AstrBot 网页聊天查询群记录”。只有一个 QQ 接入时，两个“仅多接入时”设置留空；有多个接入时，同时填写目标**QQ 平台 ID**和**机器人 QQ 号**。WebChat 查询只回复当前 ChatUI，与 QQ 好友的“上次总结后”进度分开；WebChat ID 不能自动对应你的 QQ 号，因此无法仅凭它确认你在群里被 @。

## 图片、速度与覆盖范围

- 图片、引用和合并转发可按需读取；批量工具一次最多处理 8 条消息，默认并行 4 条。图片识别依赖视觉模型，识别出的文字仍可能有误。
- `get_image` 超时后**只尝试一次**。同一消息 10 分钟内的重复请求会直接返回失败状态，不再次等待 QQ；你之后明确要求重试时可用 `refresh="true"`。超时图片应计为未解析，不能猜测内容。
- 不下载或保存图片文件。图片地址可能失效；仅使用受信任 QQ 域名的 HTTPS 地址（HTTP 地址会升级为 HTTPS），不读取 NapCat 容器本地路径。图片 URL 会发送给所选视觉模型，可能产生模型费用。
- 语音、视频、文件正文和部分卡片暂不解析；QQ 系统表情通常只得到编号。没有保存记录不代表当时无人聊天。
- 每页最多 100 条、约 16,000 字正文；有 `has_more=true` 时继续分页。`start/end` 是查询边界，`read_first_time/read_last_time/read_count_so_far` 才是实际已读记录范围和数量。
- 单条媒体处理最多约 105 秒。若 AstrBot 提前终止工具调用，可检查 `provider_settings.tool_call_timeout` 是否至少 120 秒。批量结果的 `complete_coverage` 只针对本批消息 ID，不能代表整天媒体都已读完。

## 数据与权限

记录保存在 AstrBot 数据卷的 `data/plugin_data/astrbot_plugin_group_memory/history.sqlite3`；升级插件不会覆盖它。数据库未加密，媒体线索可能包含临时图片 URL；建议停机备份并保护 SQLite/WAL 文件。默认只记录配置群的新群消息，不保存私聊、机器人自己的消息或 OneBot 通知/请求。不做撤回同步。曾安装实验版 v0.4.0 的用户需自行检查并清理该版留下的媒体归档文件。

只有 AstrBot 管理员和已配置的查询者可读取。记录按 QQ 接入、机器人账号和群号隔离；QQ群管理员身份本身不授予查询权限。启用 WebChat 时，还需单独授权 `reader_id`。工具读取的是已接收并保存的记录，无法保证覆盖插件安装前、机器人离线或被过滤的消息。

## 遇到问题

| 现象 | 先检查 |
| --- | --- |
| `/群记录状态` 显示 0 条 | 群号、插件启用状态、NapCat 事件上报；测试消息必须在插件启用后发送。 |
| `/群记录自检` 显示数据库可用但无记录 | 检查是否配置了正确群号、机器人是否在群中，以及插件启用后是否收到新群消息。 |
| 自检显示 QQ API 不可用 | 检查 NapCat 与 AstrBot 的 API 通道；收到群消息不代表 API 调用可用。 |
| 状态有记录，AI 却说没有 | 当前模型是否支持工具调用，Agent 是否启用 `qq_history_read`，查看工具日志。 |
| 文字能读，图片返回 `ApiNotAvailable` | NapCat 中机器人是否在线、反向 WebSocket 是否提供 API 调用；只有事件上报不够。 |
| 图片返回 `TimeoutError` | 本次图片未取得，稍后明确要求重试；不要在同一轮总结里逐张重复调用。 |
| 重启后记录消失 | 检查 Docker 是否持久化挂载 AstrBot 的 `data` 目录。 |

工具入口：`qq_history_groups` 列出可查群；`qq_history_read` 按日期、关键词或发言人分页查询；`qq_history_media` 读取单条媒体；`qq_history_media_batch` 一次读取 1～8 条媒体消息。发布前检查见 [验收清单](TESTING.md)。源码目录运行 `python3 -m unittest discover -s tests -q` 可执行离线测试；测试不替代 AstrBot + NapCat + 模型的实机验收。

发布安装包只包含运行所需源码、页面、README、许可证和安全说明。维护者可在仓库根目录运行 `python3 scripts/build_release.py`，生成 `dist/` 下的安装包；脚本会核对文件清单并扫描疑似个人信息和密钥。
